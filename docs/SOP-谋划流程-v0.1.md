# SOP：谋划流程 v0.1（可执行标准）

> 目标：把「用户大段描述 → 军师输出」变成**固定阶段、按需填写、少量追问**的 SOP；大段输入只出现在两个关键节点。
> 原则：**先描述块，后代码化**。每个阶段先写清「谁、何时、输入什么、输出什么、何时停」，闭环后再逐块写代码。

---

## 1. 总体流程

```
S0 背景注入（允许大段）
  → S1 目的澄清（选择/填空）
  → S2 局势拆解（表单 + ≤5 追问）
  → S3 判断与检索（用户选方向）
  → S4 推演与方案（短参数）
  → S5 输出校验（用户确认）
  → S6 执行与转折（允许大段）
  → S7 复盘（短填写）
```

---

## 2. 各阶段规则

| 阶段 | 用户输入形态 | 工具 | 产出 | 结束条件 |
|---|---|---|---|---|
| S0 背景注入 | **允许大段**：按《S0-背景速填》说清背景 | S0 速填模板 | 背景卡（原话 + 时间线） | 用户说「差不多了」或信息够触发目的 |
| S1 目的澄清 | 《S1-目标卡表单》：3–5 道选择/填空 | T0 + S1 表单 | 目标卡 | 成功/失败判据可判定 |
| S2 局势拆解 | 结构化表单 + 最多 5 条追问 | T1 提示词 + `t1_repair` 闭环 | SIR（含缺口与追问） | 完备度 ≥ 0.7 或用户确认「就这些」 |
| S3 判断与检索 | 只选方向（1–3 个候选） | T2 / T3 | 变体 + 原则 + 候选策略 | 用户选定 1–2 个方向 |
| S4 推演与方案 | 《S4-推演参数表单》：短参数/表格 | T4 / T5 / T6 + S4 表单 | 分支树 + 决策卡草案 | 分支概率/代价可解释 |
| S5 输出校验 | 确认/修改（不写长文） | T7 / T10 / T11 | 合规决策卡 | 校验通过 + 用户确认 |
| S6 执行与转折 | **允许大段**：按《S6-转折速填》补新信息 | S6 速填 + SIR 更新 + 重跑 | 修正分支 + 新决策卡 | 转折信息处理完 + **round++ + 目的变更记录** |
| S7 复盘 | 短填：结果/情绪/命中率 | T8 | 复盘记录 + 校准 | 记录入库 |

---

## 3. 大段输入的两个合法节点

1. **S0 背景注入**：一次说清背景，避免后面零碎补；
2. **S6 执行与转折**：出现关键新信息（对方变招、第三方介入、代价超预期）时集中补充。

其余阶段一律用：
- 选择题（2–5 项 + 不确定）；
- 填空（一句话/数字区间）；
- 短答（≤ 50 字）。

**禁止**：在 S1–S5 反复让用户复制粘贴长文。

**关系型分支**：先处理情绪与面子，再谈条款；优先给台阶与书面约定，避免当众催收/曝光。

---

## 4. 追问上限与停止规则

- 每次最多 5 条追问，按「影响 × 不确定 ÷ 成本」排序；
- 完备度 ≥ 0.7 或用户选择「先这样」即停止；
- 追问答「不知道」是合法输入，进入 `unknowns`，不阻塞流程；
- 信息不足时输出「条件式建议」：若 A 则 X，若 B 则 Y，而不是硬编一个结论。

---

## 5. 每个阶段的「描述块」

每个工具/链路先写一块，格式统一：

1. 目的（解决什么）
2. 输入（字段/来源）
3. 处理（步骤/规则/排序）
4. 输出（结构/示例）
5. 边界（不做什么）
6. 验收（用例/通过标准）
7. 代码化计划（文件/依赖/优先级）

> **11/11 工具已代码化**（`tools/`）；描述块保留作设计依据。

---

## 7. 工程落地（一键链路）

- `tools/run_pipeline.py --case tools/cases/case2 --out <目录>`：按 S0→S8 顺序调用 T0–T11；
- 案例 `tools/cases/case2` 覆盖：背景、目标卡、SIR、game_input、plans、tree_spec、决策卡；
- 实测 11 个步骤全部通过（T0/T1/T2/T3/T4/T5/T6/T7/T8/T10/T11）；
- 唯一未自动化的是 T1 的「自然语言→SIR 抽取」，目前需要 LLM 提示词完成。
- 可视化：`tools/render_report.py --case <案例> --out <report.html>`，生成可离线打开的报告（分支树/决策卡/风险/心性）。
